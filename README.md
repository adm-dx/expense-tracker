# Expense Tracker

Трекер доходов и расходов: мультивалютные транзакции с конвертацией по сегодняшнему курсу, категории и теги, отчёты, пользовательские настройки (тема, валюты, город для погоды) и виджет погоды. Монорепозиторий: фронтенд на Next.js, бэкенд на NestJS, PostgreSQL.

## Возможности

### Аккаунт и сессия

- Регистрация и вход по email и паролю; JWT access-токен и refresh-токен (хранится в БД в хэшированном виде, с ротацией и отзывом всей цепочки при повторном использовании).
- Все маршруты API закрыты по умолчанию, публичны только регистрация, вход, обновление токена и выход.
- Смена пароля в настройках: проверяется текущий пароль, все сессии на других устройствах завершаются, текущая получает новую пару токенов.
- Данные одного пользователя не «протекают» в следующую сессию в той же вкладке: сторы очищаются при входе, выходе и ошибке авторизации.

### Транзакции

- Доходы и расходы: сумма, валюта, категория, тег, описание, дата.
- Таблица с пагинацией (10 / 20 / 50 строк на страницу, выбор запоминается).
- Фильтр по периоду: «This month», «Last month», «Last 30 days», «This year» или произвольный диапазон, кнопка сброса. Выбор хранится **для каждого пользователя** отдельно и переживает перезагрузку и повторный вход; пресет пересчитывается от текущей даты.
- Фильтр по тегу (общий для таблицы и итогов).
- Карточки с итогами (доходы, расходы, баланс) за выбранный период.

### Валюты

- Каталог из 22 валют (EUR, USD, GBP, CHF, RSD, HUF, PLN, CZK, …); везде показываются как `EUR (€)`.
- Пользователь сам включает нужные валюты в настройках; EUR включена всегда.
- Транзакция хранится в той валюте, в которой введена; конвертация выполняется **при чтении** по сегодняшнему курсу в выбранную валюту отображения (переключатель в шапке).
- При удалении валюты все транзакции в ней переводятся в EUR по текущему курсу (с подтверждением).
- Курсы — ExchangeRate-API (open access, без ключа), кэшируются на сутки; если провайдер недоступен, используются последние полученные курсы.

### Категории

- Набор категорий по умолчанию создаётся при регистрации.
- Управление в настройках: создание, переименование, выбор иконки (lucide) из сетки, счётчик транзакций.
- Удаление категории с транзакциями — с переносом их в другую категорию одной операцией.

### Теги

- Управление тегами в настройках: создание, переименование, удаление, счётчик транзакций.
- Тег назначается транзакции в форме (пока не больше одного на транзакцию).
- Удалить можно и используемый тег — он снимается со всех транзакций.

### Отчёты

Страница `/reports` с двумя вкладками:

- **By category** — суммы и количество транзакций по категориям, доходы и расходы отдельно, с собственным фильтром по периоду (тоже сохраняется для каждого пользователя).
- **By tag** — выбор тега и по нему за всё время, без выбора дат: итоги доходов, расходов и баланса, помесячная диаграмма доходов и расходов и таблица месяцев.

### Настройки

- **Тема**: светлая, тёмная или системная, плюс 12 цветовых схем shadcn/ui (slate, zinc, stone, gray, neutral, red, rose, orange, green, blue, yellow, violet) с живым предпросмотром; без мигания при загрузке.
- **Валюта отображения** и **список включённых валют**.
- **Категории** и **теги**.
- **Местоположение для погоды**: позиция браузера или город, найденный поиском.
- **Смена пароля**.
- **Сброс настроек** к значениям по умолчанию (список валют сохраняется).

### Погода

- Виджет в шапке: текущая температура и погода, название города, прогноз на 5 дней, кнопка обновления.
- Данные — Open-Meteo, названия городов — OpenStreetMap Nominatim (без ключей); погода кэшируется на 30 минут, названия — на сутки.
- Обновляется раз в час и при возврате на вкладку; без доступа к геолокации (и без выбранного города) виджет скрыт.

## Стек технологий

### Frontend

- **Next.js 16** с App Router
- **React 19**
- **TypeScript 6** (strict mode)
- **Tailwind CSS 3** (намеренно без перехода на v4)
- **shadcn/ui** на **Radix UI**, иконки **lucide**
- **Zustand 5** — состояние
- **React Hook Form 7** + **Zod 4** — формы и валидация

### Backend

- **NestJS 12** (+ `@nestjs/cqrs`, `@nestjs/jwt`, `@nestjs/config`)
- **Prisma 7** ORM с драйвер-адаптером `@prisma/adapter-pg`
- **PostgreSQL 16**
- **TypeScript 6** (strict mode)
- **class-validator** — валидация DTO

### Инструменты

- **npm workspaces** — управление монорепозиторием
- **ESLint 9 + Prettier 3** — линтинг и форматирование
- **Jest 30** + React Testing Library + Supertest — тесты
- **Docker Compose** — локальная и тестовая базы данных

### Требования

- **Node.js 24.9+** (NestJS 12 работает с 20.19+ / 22.12+, но тестам нужен `require(esm)` в Jest, а он есть только с 24.9)
- **Docker** — для PostgreSQL

## Установка

### 1. Клонируйте репозиторий и установите зависимости

```bash
npm install
```

Prisma Client генерируется автоматически после установки (в `apps/api/src/generated/prisma`, не хранится в git).

### 2. Настройте переменные окружения

```bash
cp .env.example .env
```

| Переменная                                     | Назначение                                                       |
| ---------------------------------------------- | ---------------------------------------------------------------- |
| `DATABASE_URL`                                 | Строка подключения к PostgreSQL (по умолчанию — Docker на :5432) |
| `API_PORT`, `API_URL`                          | Порт и адрес API (3001)                                          |
| `NEXT_PUBLIC_API_URL`                          | Адрес API для фронтенда                                          |
| `WEB_URL`                                      | Адрес фронтенда, разрешённый в CORS                              |
| `JWT_ACCESS_SECRET`, `JWT_ACCESS_EXPIRES_IN`   | Секрет и срок жизни access-токена (15m)                          |
| `JWT_REFRESH_SECRET`, `JWT_REFRESH_EXPIRES_IN` | Секрет и срок жизни refresh-токена (7d)                          |
| `EXCHANGE_RATES_URL`                           | API курсов валют (`https://open.er-api.com/v6`)                  |
| `WEATHER_URL`, `GEOCODING_URL`                 | Open-Meteo и Nominatim                                           |
| `TEST_DATABASE_URL`                            | Тестовая БД (необязательно, по умолчанию — :5433)                |

Внешним сервисам ключи не нужны.

### 3. Запустите PostgreSQL

```bash
npm run db:start
```

### 4. Примените миграции Prisma

```bash
cd apps/api
npx prisma migrate dev
cd ../..
```

Prisma CLI берёт `DATABASE_URL` из корневого `.env` (через `apps/api/prisma.config.ts`).

## Запуск проекта

```bash
npm run dev           # Фронтенд и бэкенд вместе
npm run dev:web       # Только фронтенд — http://localhost:3000
```

## Полезные команды

### База данных

```bash
npm run db:start      # Запустить PostgreSQL
```

Удалить данные полностью: `docker compose -f docker/docker-compose.yml down -v`.

### Тесты

Все тесты лежат в `tests/` и делятся на три уровня:

| Уровень     | Где                        | Что проверяет                                              | Команда                    |
| ----------- | -------------------------- | ---------------------------------------------------------- | -------------------------- |
| Unit        | `tests/unit/{api,web}/**`  | Сервисы и обработчики с моками, логика, сторы и компоненты | `npm test`                 |
| Integration | `tests/integration/api/**` | Настоящее Nest-приложение и настоящий Postgres             | `npm run test:integration` |
| E2E         | `tests/e2e/api/**`         | Пользовательские сценарии через HTTP                       | `npm run test:e2e`         |

```bash
npm test                     # Unit-тесты (без БД и сети, ~3 с)
npm run test:watch           # Unit-тесты в режиме watch
npm run test:cov             # Покрытие unit-тестами (в ./coverage)

npm run db:test:start        # Поднять тестовую БД (Postgres на :5433, данные в tmpfs)
npm run test:integration     # Integration-тесты
npm run test:e2e             # E2E-сценарии
npm run test:cov:integration # Покрытие API integration-тестами
npm run test:all             # Все три уровня по очереди
npm run db:test:stop         # Удалить тестовую БД

# Один файл или один тест
npm test -- tests/unit/api/modules/auth/auth.service.spec.ts
npm test -- -t "ConflictException for a duplicate email"
```

Тесты не читают `.env` и отказываются работать с базой, имя которой не оканчивается на `_test`. Внешние провайдеры (курсы, погода, геокодинг) в тестах заменены фейками — сеть не нужна.

## API

Все маршруты, кроме отмеченных «публичный», требуют access-токен (`Authorization: Bearer …`).

| Метод и путь                                   | Описание                                                       |
| ---------------------------------------------- | -------------------------------------------------------------- |
| `POST /auth/register`, `/auth/login`           | Регистрация и вход (публичные)                                 |
| `POST /auth/refresh`, `/auth/logout`           | Обновление пары токенов и выход (публичные)                    |
| `GET /auth/me`                                 | Текущий пользователь                                           |
| `POST /auth/change-password`                   | Смена пароля                                                   |
| `GET/POST /transactions`                       | Список (фильтры, пагинация, `?currency=`) и создание           |
| `GET/PATCH/DELETE /transactions/:id`           | Одна транзакция                                                |
| `GET /transactions/summary`                    | Итоги за период и разбивка по категориям                       |
| `GET /transactions/summary/by-tag`             | Разбивка по тегам                                              |
| `GET /transactions/summary/by-tag/history`     | Один тег за всё время по месяцам (`?tagId=`)                   |
| `GET/POST /categories`                         | Категории (со счётчиком транзакций) и создание                 |
| `GET/PATCH/DELETE /categories/:id`             | Одна категория; `DELETE ?reassignTo=<id>` переносит транзакции |
| `GET/POST /tags`, `GET/PATCH/DELETE /tags/:id` | Теги                                                           |
| `GET/PUT/PATCH/DELETE /settings`               | Настройки пользователя (`DELETE` — сброс к умолчаниям)         |
| `POST /settings/currencies`                    | Включить валюту                                                |
| `DELETE /settings/currencies/:code`            | Отключить валюту, переведя её транзакции в EUR                 |
| `GET /exchange-rates`                          | Текущие курсы                                                  |
| `GET /weather?lat=&lon=`                       | Погода и прогноз на 5 дней                                     |
| `GET /weather/places?q=`                       | Поиск города по названию                                       |

## Архитектура

### Бэкенд

- Каждый модуль (`auth`, `users`, `categories`, `tags`, `transactions`, `exchange-rates`, `weather`, `settings`) устроен как controller → service → repository; к Prisma обращается только репозиторий.
- Модули общаются между собой через **CQRS** (`CommandBus` / `QueryBus` / `EventBus`): модуль публикует команды, запросы и события в папке `contracts/`, а другие импортируют только их.
- Глобальные `ValidationPipe` и CORS настраиваются в `src/app.config.ts`, чтобы тесты поднимали приложение с теми же правилами.
- Внешние провайдеры (курсы, погода, геокодинг) подключены через DI-токены и в тестах заменяются фейками.

### Фронтенд

Код в `apps/web/src` организован по **Feature-Sliced Design**:

- `shared` — UI-примитивы shadcn/ui, HTTP-клиент, утилиты, конфигурация;
- `entities` — бизнес-сущности и их сторы (сессия, транзакции, категории, теги, настройки, валюта, погода, отчёт);
- `features` — пользовательские действия (вход, формы, фильтры, настройки, виджет погоды);
- `widgets` — составные блоки (шапка, боковое меню, таблица и итоги транзакций, отчёт, панель настроек);
- `app` — маршруты Next.js: `/` (транзакции), `/reports`, `/settings`, `/profile`, `/login`, `/register`.

Импорты идут только «вверх»: `shared → entities → features → widgets → app`.

### База данных

Модели: `User`, `RefreshToken`, `Category`, `Tag`, `Transaction` (сумма `Decimal(12,2)` в своей валюте, теги — `jsonb`-массив с GIN-индексом), `UserSettings` (один `jsonb`-документ на пользователя). Все запросы ограничены `userId`; удаление пользователя каскадно удаляет его данные.

### Общие пакеты

- **@expense-tracker/types** — типы API и общие каталоги (валюты, иконки категорий, цветовые схемы, настройки по умолчанию)
- **@expense-tracker/config** — общие конфигурации ESLint, Prettier, TypeScript

Подробные соглашения для разработки — в [CLAUDE.md](CLAUDE.md).
